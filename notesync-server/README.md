# notesync-server

Сервер блокнота: хранит заметки, ревизии, конфликтные версии и лог. Rust, axum + SQLite.

Главное правило: сервер **никогда не выбрасывает присланный текст**. Если клиент правил не последнюю
ревизию, его текст сохраняется как отдельная конфликтная версия, а основная заметка не меняется.
Тексты автоматически не склеиваются.

## Запуск

Нужен свежий Rust (собрано и проверено на 1.97; на старых версиях зависимости могут не собраться).

    cargo run --release

Настройки через переменные окружения (всё необязательно):

| Переменная       | По умолчанию | Что делает                                         |
|------------------|--------------|----------------------------------------------------|
| NOTESYNC_PORT    | 8787         | порт                                               |
| NOTESYNC_DB      | notes.db     | файл базы SQLite                                   |
| NOTESYNC_TOKEN   | (из файла)   | токен; если не задан — берётся/создаётся `notes.db.token` |

Токен создаётся при первом запуске и лежит в файле `<база>.token`. Его же нужно ввести в приложении
на телефоне и в клиенте на ПК. Сервер слушает 0.0.0.0, так что телефон в той же сети до него достучится.
Если не отвечает — проверьте, что порт открыт в файрволе ПК (и что в роутере не включена изоляция клиентов Wi-Fi).

## Проверка

    ./test.sh

Сам поднимет сервер на порту 18787 с временной базой и прогонит сценарии: токен, создание, правка,
повтор правки, конфликт, одинаковый текст при старой ревизии, resolve (все три действия),
удаление, список изменений, UTF-8 (иероглифы). Нужны bash, curl, python3.
Чтобы проверить уже запущенный сервер: `NOTESYNC_TOKEN=... ./test.sh http://127.0.0.1:8787`.

## API

Все запросы (кроме /health) с заголовком `Authorization: Bearer <токен>`, тела в JSON.

| Запрос | Что делает |
|--------|------------|
| GET /health | имя и версия, без токена |
| GET /notes?since=N | заметки (и удалённые) с seq > N, плюс текущий максимальный seq. В заметке есть `conflicts` — число нерешённых конфликтов |
| GET /notes/{id} | одна заметка |
| PUT /notes/{id} | тело: `body`, `base_rev` (0 для новой), `device_id`, `edit_id`. Ответ: `status` = `ok` или `conflict`, `rev`, `seq`, при конфликте `conflict_version_id` |
| DELETE /notes/{id}?base_rev=N&device_id=X | мягкое удаление; при несовпадении rev — `status: conflict`, заметка остаётся |
| GET /notes/{id}/versions | история и конфликтные версии (новые сверху) |
| POST /notes/{id}/conflicts/{version_id}/resolve | тело: `action` = `keep_server` / `use_this` / `keep_both`, `device_id` |
| GET /log?limit=N | журнал событий (create, update, conflict, resolve, delete) |

`edit_id` — уникальный id каждой правки (например, uuid). Если ответ потерялся и клиент отправил ту же правку
повторно, сервер вернёт прежний ответ, а не создаст дубль.

Удалённые заметки приходят в `GET /notes?since=N` с `deleted: true`, чтобы клиенты тоже их убрали.
